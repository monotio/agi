# LOGIC language

The compiler accepts a compact AGI source dialect and emits native LOGIC
bytecode. The [assembler](../src/logic/assembler.ts) and
[syntax parser](../src/logic/syntax.ts) define its grammar. New games use profile
`2.936`; imported games use their selected interpreter profile.

## Source syntax

```agi
#message 1 "You are standing in a clearing."
#define fDoorOpen 42

start:
if (isset(f5) && !isset(fDoorOpen)) {
  print(1);
  print("The door is closed.");
} else {
  if (said("open", "door") || said("unlock", "door")) {
    set(fDoorOpen);
    goto done;
  }
}
done:
return;
```

Commands take comma-separated operands in parentheses and end with `;`.
`return;` ends the current LOGIC call. `if (condition) { ... }` can have an
`else { ... }` block. Labels end with `:` and `goto label;` jumps to them;
labels share one namespace across the document, including nested blocks.
`//` comments run to the end of a line. Identifiers and command names are
case-sensitive; use the spellings in the tables below. Numbers are decimal.

Variables, flags, screen objects, messages and strings use `v5`, `f5`, `o5`,
`m5` and `s5`, or numeric operands. `#define name number` gives a numeric value
an alias. Byte operands range from 0 to 255; messages are numbered 1 to 255.
Commands validate operands against their declared kinds and the active profile.

`#message N "text"` sets a message slot. Inline strings in message operands
allocate slots automatically. `#message N` declares an absent slot;
`#message N ""` declares a present empty message. Message characters represent
bytes. String escapes are `\n`, `\r`, `\\`, `\"` and `\xNN`; keep literal text
on one source line. Other `#` directive lines are ignored by the lexer; source
includes and macros belong outside this dialect.

## Conditions

Use condition calls with `!`, `&&`, `||` and parentheses. The compiler converts
boolean expressions into AGI's AND of OR groups. A parenthesized single condition
also preserves an explicit one-term OR group: `if ((isset(f1)))` emits the group
markers, while `if (isset(f1))` emits the predicate directly.

`said("open", "door")` resolves words through WORDS. Numeric group IDs are
accepted too. `"*"` means any one word (group 1) and `"..."` means the rest of
the line (group 9999), subject to the profile. `"anyword"` and `"rol"` are
aliases when the dictionary has no entries with those spellings. Supply WORDS to
the compiler or [language server](editor-setup.md) for quoted vocabulary.

## Commands

These tables are generated from
[commandReference.ts](../src/logic/commandReference.ts). Operand names describe
the expected kinds. Profile selection controls available commands and behavior.
Regenerate after changes with:

```bash
node --experimental-strip-types scripts/generate-logic-reference.ts
```

`--check` verifies the committed tables; `test/docs.test.ts` runs it in the gate.

## Extending the language

For a command, add its opcode and operand contract in
[opcodes.ts](../src/logic/opcodes.ts), its help in
[commandHelp.ts](../src/logic/commandHelp.ts), and any specialized signature or
help in `commandReference.ts`. Implement its interpreter behavior under
`src/runtime/` using the selected profile's specification and original binary
evidence, recorded in [fidelity](fidelity.md). Add hand-computed bytecode and
runtime assertions, see them fail first, then regenerate these tables. Preserve
released profile IDs and opcodes.

For a diagnostic, change the relevant parser, assembler or analysis check in
[language.ts](../src/logic/language.ts) and its supporting modules. Add a minimal
invalid source and assert its range, severity and message in the language tests.
For completion, extend the shared snapshot's completion handling and assert the
item, insertion text and replacement range. Both the browser analysis worker and
the stdio server use the shared service; project bindings are added by
[projectLanguage.ts](../src/authoring/projectLanguage.ts). Exercise the wire tests
when changing protocol output and the browser spec when changing visible behavior.
